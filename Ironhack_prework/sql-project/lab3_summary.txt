ADVANCED SQL TECHNIQUES LAB - SUMMARY


WHAT I LEARNED:
This lab covered the most sophisticated SQL concepts including scalar subqueries, inline subqueries (derived tables), correlated subqueries, Common Table Expressions (CTEs), window functions (ROW_NUMBER, RANK, DENSE_RANK, LAG, LEAD), CASE statements, and advanced data cleaning functions. These techniques enable solving complex business problems through advanced data analysis.

SUBQUERIES VS CTEs:
- Scalar Subqueries: Single value lookups in SELECT/WHERE clauses, simple but can be inefficient if repeated
- Inline Subqueries: Temporary tables in FROM clause for complex filtering and joining
- Correlated Subqueries: Reference outer query, execute row-by-row (potentially slow for large datasets)
- CTEs: More readable than nested subqueries, can reference themselves (recursive), improve query maintainability

WINDOW FUNCTIONS BENEFITS:
Window functions like ROW_NUMBER, RANK, DENSE_RANK, LAG, and LEAD are more efficient than self-joins for:
- Ranking and numbering rows within groups
- Calculating running totals and moving averages
- Finding previous/next values without complex joins
- Top N per group queries without subqueries

CASE STATEMENTS APPLICATION:
CASE statements enable conditional logic in SQL:
- Simple categorization in SELECT clause
- Conditional aggregation (SUM case when..., COUNT case when...)
- Customer segmentation based on spending tiers
- Data quality checks and transformations

ADVANCED DATA CLEANING:
String manipulation (SUBSTR, INSTR, REPLACE) for email extraction and data standardization
Date functions (JULIANDAY, DATE) for calculating tenure and temporal analysis
Numeric functions (ROUND, mathematical operations) for percentage calculations
NULL handling (COALESCE) for data quality and completeness

PERFORMANCE CONSIDERATIONS:
- CTEs improve readability without significant performance penalty for moderate datasets
- Window functions more efficient than self-joins or correlated subqueries
- Filter early with WHERE before expensive operations like aggregation
- Indexes recommended on frequently used join and filter columns (customer_id, order_date)
- Correlated subqueries should be avoided when joins or window functions can replace them

KEY INSIGHTS:
1. Complex queries often combine multiple advanced techniques
2. Readability is important - CTEs make queries more maintainable
3. Window functions superior to self-joins for analytical queries
4. CASE statements enable business logic within SQL
5. Data cleaning functions essential for real-world messy data

CHALLENGES FACED:
- Understanding the difference between when to use subqueries vs CTEs vs window functions
- Recognizing performance implications of correlated subqueries on large datasets
- Properly partitioning and ordering in window functions
- Handling NULL values in aggregations and calculations

BEST PRACTICES:
- Use CTEs for readability and modularity
- Use window functions instead of self-joins when possible
- Use joins instead of correlated subqueries for better performance
- Apply WHERE filters before GROUP BY when possible
- Document complex query logic with comments
- Test query performance on real datasets before production

REAL-WORLD APPLICATION:
These advanced techniques are essential for:
- Building data warehouses and ETL pipelines
- Creating business intelligence dashboards and reports
- Performing customer segmentation and RFM analysis
- Detecting data quality issues
- Time-series and trend analysis
- Rank and percentile calculations
